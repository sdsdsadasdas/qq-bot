# qq-bot — QQ 消息监测与自动回复

基于**窗口截图 + Windows 内置 OCR** 的 QQ 消息监测与自动回复脚本。
不注入、不 hook、不读数据库，只用公开的 Win32 API、UI Automation 和系统自带的 OCR 引擎。

> ⚠️ **先说清楚风险，再往下看**
>
> 1. **这是把自动回复挂在真人 QQ 号上**，等于用你的身份对真人说话。如果对方以为在跟你本人聊，
>    那是欺骗，不是自动化。请让相关的人知道这是自动回复，或者**只拿小号测**。
> 2. 本方案走的是 GUI 自动化，不修改 QQ 进程，**没有注入类框架的封号风险**。
>    但它仍然是自动化操作 QQ，是否合规请自行判断，别挂常用号。
> 3. 上线前默认是 `dryRun`（只看不发）。这个默认值是故意的，别直接改掉。

## 🔑 两个关键发现（本项目最有价值的部分）

### 发现一：UIA 必须主动激活，否则什么都读不到

QQ NT 是 Chromium/Electron 外壳，而 **Chromium 默认不构建无障碍树**，
普通 UI Automation 客户端只能看到一个 HWND 外壳。

同一个窗口，激活前后：

| | 后代节点数 | 能读到的内容 |
|---|---|---|
| 直接 UIA | **1** | 只有根 Window |
| 直接 MSAA `IAccessible` | 11 | 全是无名容器，零文本 |
| **发 `WM_GETOBJECT` + `OBJID_CLIENT` 后** | **~340** | **消息、发送者昵称、输入框内容、发送按钮** |

激活方式就是真实辅助技术（讲述人、NVDA）做的事。`tools/uia-read.ps1` 内置这一步。

> 我最初判定"QQ 不暴露内容、只能走 OCR"，**那个结论是错的**。
> 不是 QQ 不暴露，是我没激活。激活后 UIA 远胜 OCR：精确、有坐标、不受 DPI 影响、
> 不需要标定几何参数，还能拿到 **OCR 读不准的发送者昵称**。

### 发现二：Ctrl 修饰键根本传不进 QQ 的输入框

这是很多失败的根因，用**逐步 UIA 校验**测出来的：

```
按 Ctrl 下去          -> box = 'SEED9'
再按 A               -> box = 'SEED9a'    ← A 变成了普通字符！Ctrl 丢了
再按 Ctrl 抬起       -> box = 'SEED9a'
按 Delete            -> box = 'SEED9a'    ← 没东西可删
之后 End + 连续退格  -> box = ''   ✓
```

**所以 `Ctrl+A` / `Ctrl+V` 这类操作在 QQ 输入框上注定失败。**

这也解释了本项目早期那个 bug：最初用剪贴板 `Ctrl+V` 粘贴，
结果只发出了一个孤零零的 `v` 字符，还触发了自我循环刷屏。

**可用与不可用清单：**

| 操作 | 结果 |
|---|---|
| 逐字符 Unicode `SendInput` 打字 | ✅ 有效 |
| `End` + 多次 `Backspace`（紧凑按下/抬起对） | ✅ 有效，可靠清空 |
| `Ctrl+A` / `Ctrl+V` / 任何 Ctrl 组合 | ❌ 修饰键丢失 |
| 慢速退格（每次一个 SendInput + 长间隔） | ❌ 无效 |
| UIA `ValuePattern` 设置输入框 | ❌ 聊天输入框不是 Edit 控件（只有搜索框是） |

### 附带发现：UIA 解析消息的三个坑

1. **群名不带成员数。** OCR 读到的是 `示例群（10）`，UIA 读到的是 `示例群`。
   靠「群名带成员数」判断群聊在 UIA 路线下失效 → 群聊被判成私聊 →
   「群里只在被 @ 时回复」这道闸门形同虚设。改用 UIA 自己的证据（`群聊成员`/`群主`/`管理员`）。

2. **群头衔会插进消息正文。** 实测群头衔（如 `群友己`、`示例群友`）
   渲染在发送者行的 y-1 上，而元素按 (y, x) 排序、头衔 x 更大，所以头衔
   **排在它自己的 LV 徽章之前**。必须预先收集所有 LV 行的 y 坐标做「向前看」判定，
   用「上一个 LV 行」会永远错开一行。

3. **自己的消息没有 LV 徽章。** QQ 不给自己发的内容显示等级徽章，
   所以不能靠坐标区分自己/他人。防自嗨靠 `gate.js` 的 `sentReplies` 文本比对。

## Windows PowerShell 5.1 的三个坑（都实测踩过）

1. **无 BOM 的 UTF-8 会被当 GBK 解码。** 中文注释变乱码 → 引号错位 → 语法错误；
   中文路径变乱码 → 找不到文件。
   → 对策：工具脚本源码**保持纯 ASCII**（中文 UI 名用 `[char]0x53D1` 这种转义），
   或给文件加 UTF-8 BOM。

2. **LF-only 换行的脚本，解析器会算错行号**，还会连带报出假语法错误
   （实测：一个含 here-string 的 LF-only 脚本报 4 个不存在的错误，改成 CRLF 后全消失）。
   → 对策：`.ps1` 一律 CRLF。

3. **`param()` 块里不能夹注释行。** 实测那行注释会把紧随其后的参数**整个吃掉**
   （`$ClickX` 从 AST 里消失，调用时报 "parameter cannot be found"）。
   → 对策：参数说明写在 `param()` 外面。

另外一个通用的：**PowerShell 里相对路径按「会话初始目录」解析，不是按 `cd` 后的目录**。
实测 `Parser::ParseFile('tools\\x.ps1')` 和 `ocr-image.ps1 -ImagePath '.x.png'` 都因此找不到文件，
却报成别的问题，白查了很久。→ 对策：脚本与命令一律用绝对路径。

## 为什么是 OCR，而不是读取消息接口

这台机器上的实测过程（不是推测）：

| 路线 | 实测结果 |
|---|---|
| UI Automation 直读 | ❌ 只有 1 个节点（根 Window） |
| 激活无障碍后（`WM_GETOBJECT` + `OBJID_CLIENT`）再读 UIA | ❌ 9 个后代，**全是无名 `Pane` 容器**，零文本 |
| MSAA / `IAccessible` 反射遍历 | ❌ 走了 11 个节点，**零文本** |
| 官方接口 | ❌ 官方 QQ 客户端不开放本地消息接口 |

根因：QQ NT 是 Chromium/Electron 外壳，网页内容不暴露给无障碍 API。
所以**像素是唯一可靠的来源**，于是走截图 + OCR。

好消息是系统自带的 OCR 就能用，**零额外依赖**：

```
Windows.Media.Ocr.OcrEngine → AvailableRecognizerLanguages = ["zh-Hans-CN"]
```

## 对话连贯性：它记不记得自己上次说了什么

**能，但这不是自动的** —— 得专门做，否则它每次都是"失忆"状态。

### 两个必须解决的问题

**问题 1：机器人看不到自己发的话。**

UIA 只能读到当前渲染的那一批消息（实测一轮 12~14 条）。
消息一滚出渲染范围就再也读不到 —— **包括机器人自己刚发出去的话**。

实测抓到过：某一轮解析出 12 条消息，`self` 数量是 **0** ——
它自己的回复一条都不在上下文里。

**问题 2：自己说过的话被当成"别人的转述"。**

早期版本把整个历史塞进一条 `user` 消息，自己说的话写成 `我：xxx`：

```
user: 以下是最近的群聊记录…\n群友丙：有人吗\n我：在的\n群友乙：我电脑又蓝了
```

模型是在**读一份别人转述的对话记录**，而不是在**延续自己的对话**。
这跟"记得自己说过什么"是两件事。

### 现在怎么做的

**① 持久历史缓冲**（存在 `state.json` 的 `history`，跨轮累积）

```json
"history": [
  { "side": "incoming", "sender": "群友丙", "text": "有人吗" },
  { "side": "self", "sender": "", "text": "在的" },
  ...
]
```

上限 `llm.historyBuffer`（默认 60 条）。去重靠 `histSeen` 指纹，
而且**发送成功后立刻补记自己的回复** —— 不能等下一轮读回来，
那时它可能已经滚出渲染范围，就永远记不住了。

**② 自己的话渲染成真正的 `assistant` 轮次**

```json
[
  { "role": "system",    "content": "…人设…" },
  { "role": "user",      "content": "群友丙：有人吗" },
  { "role": "assistant", "content": "在的" },              ← 它自己的话
  { "role": "user",      "content": "群友乙：我电脑又蓝屏了" },
  { "role": "assistant", "content": "啊这 又蓝了？" },
  { "role": "user",      "content": "群友乙：嗯 第三次了\n\n现在需要你回复最后这一条：\n\"那换个内存条试试\"\n\n直接给出你要打的那句话。" }
]
```

轮次边界跟着"谁在说话"走：连续的 incoming 合并成一条 `user`，
自己的话单独是 `assistant`。

### 效果对比（真实 API）

```
对方说：你刚不是说不信吗
它自己刚才说的是：啊这 又蓝了？（其实没说"不信"）

【无持久历史】→ (・∀・) 我改主意了不行嘛     ← 认下了自己没说过的话
【有持久历史】→ 我啥时候说过                 ← 记得自己说过什么，能反驳
```

### 顺手修掉的时间戳噪声

实测 QQ 有时把时间戳和消息渲染在同一行（`打王者啊20:44`），
于是它被当成正文发给模型。`stripTrailingTimestamp()` 负责剥掉它。

> **踩过的坑**：第一版正则写成 `^(.*\S)\s*(\d{1,2}:\d{2})$`，
> `.*` 是**贪婪**的，会把小时的第一位也吃进去 ——
> `打王者啊20:44` 被剥成 `打王者啊2`。要写成惰性的 `.*?`。

用 `node tools/test-context.mjs` 验证（29 个用例）。

## 图形控制台（推荐用它启动）

**双击 `机器人控制台.cmd`** —— 会打开一个本地网页界面，在浏览器里管理机器人。

界面里能做的事：

界面分**三页**（以前七张卡挤在一张长页面上，找一样东西要滚半天）：

| 页 | 放什么 |
|---|---|
| **主界面** | 启停机器人、实时日志；「自动轮询」（默认收起，因为它会动你的鼠标） |
| **未接入 API** | 不花钱那一套：**固定回复池** + **自定义规则**（关键词 → 一组回复） |
| **接入 API** | 厂商 / 模型名 / **API key** / API 地址 / 上下文条数 / 超时 / tokens / 思考开关；AI 接管模式；**人设**（提示词 + 它的人生 + 它的记忆，都是这张卡里的子项）；系统消息过滤 |

> 记忆和人生原来各占一页，现在**收进「人设」这张卡当子项**了 ——
> 因为它们是"某个身份"的属性：切人设就该连记忆和人生一起换。
> 分成三页之后，「我是谁」这件事只有一处能改，不会出现"人设换了、人生没换"。

「回复行为」（白名单、概率、发送间隔、被 @ 必回、dryRun、长度上限）
两个模式都要用，所以那张卡做成**同一张卡跟着当前页走** ——
在「未接入 API」和「接入 API」两页都能改，但页面里始终只有一份
（复制成两份就会出现两个 `id="whitelist"`，改了一个保存的是另一个，而且不报错）。

**API key 默认打码显示**（`sk-e8************f345`），要看全文得显式点「显示」。
key 写进项目的 `.env`，其余设置写 `config.json`。改完点「保存」，重启机器人后生效。

### 记忆：清空 ≠ 删除（用户报的「清空记忆后无法删除会话」）

记忆面板里每个会话旁边有两个动作，语义**故意分开**：

| 动作 | 效果 |
|---|---|
| 「清空这个会话的记忆」 | 抹掉内容，但这个会话**还在列表里**（空壳） |
| 会话旁边的小「删」 | **连文件一起删掉**，列表里不再有它 |

原来只有清空，于是用户清完发现"那个会话还杵在列表里、点不掉也没别的地方能删"。
两个动作都留着，是因为这是两种需求：*让它忘掉这个会话的内容*（清空更安全，文件结构还在）
和 *我不想再看到这个会话*（删除）。删除不可逆，所以弹一次确认。

> 实现上有一处必须自己守：请求里带来的会话名**不能直接拼路径**。
> 服务端只认"自己刚列出来的那些文件"（`listConversations`），再取 `basename`
> 并确认它落在记忆目录里 —— 否则一个 `../../config.json` 就能把配置删了。
> 删除用 `unlinkSync`（`fs.rmSync` 在 Z: 盘上是静默不生效的）。

### 自定义规则：自己加提示词（不接 API 时）

不接大模型时，「什么话 → 回什么」本来只能改 `config.json` 里的 `fallback.rules`。
现在在控制台「未接入 API」页里直接加：

- 一条规则 = **匹配写法**（正则，不会写就写关键词，用 `|` 隔开多个）+ **一组回复**（一行一句）
- **顺序就是优先级**，从上往下试、命中就停，`↑ ↓` 调顺序
- 匹配写法不是合法正则时**不报错也不失效**：退化成「包含这段字」，
  界面会当场写清楚这一点（否则你会以为自己写的正则生效了）
- 「**试打一句**」用的是**界面上还没保存的**那份规则 —— 加完立刻能验，不用先保存

> ⚠ 内置意图（打招呼/问句/感谢/晚安…）默认**先**匹配，所以给「在吗」写的规则
> 永远轮不到（greeting 会先把它接走）。想要你的规则说了算，勾上
> 「我的规则优先于内置意图」（= `fallback.customRulesFirst: true`）。
> 试打结果里会直接告诉你「规则命中了，但被内置意图抢走了」。

### 自动轮询其它聊天（会动你的鼠标）

QQ 一次只渲染**一个**聊天，没有后台接口 —— 想看别的会话，只能替你去点会话列表。
`autoSwitch` 就是干这个的，在「主界面 → 自动轮询」里配：

| 参数 | 说明 |
|---|---|
| `scope` | `all`＝会话列表里每一个都轮（**推荐**：谁发消息都能看见，回不回仍由白名单决定）／`whitelist`＝只轮白名单／`list`＝只轮 `conversations` |
| `settleMs` | 点完等多久再读（默认 1500ms；太短会读到上一个会话的消息 → 会回错人） |
| `minGapMs` | 两次切换至少间隔（默认 3000ms） |
| `pauseWhenActive` + `activeIdleMs` | **你一动键鼠就暂停**，闲置够 `activeIdleMs`（默认 4000ms）才继续 |

最后一条不是客气：Windows 不允许后台进程在你活跃时抢前台，硬点的话那一下只会变成
「激活窗口」，而光标已经被挪走了 —— 你正在打的字会掉进 QQ 里。
读不到空闲时间时**不拦**（宁可偶尔抢一下，也不要因为一个探测失败让轮询永远停摆）。

界面上还有个「读一次会话列表看看会轮哪些」：只读、不点，按下去就知道当前配置会轮到哪几个。

**开全量轮询顺带修好的两个错位**（都是"以前只有一个会话，所以从没暴露"）：

1. **队列按会话挑**：回复是往**当前屏幕显示的那个**聊天发的。以前拿队头就发，
   轮询之后会把「测试群」排队的那句话在轮到私聊那一屏时**发进私聊**。
   现在只取属于当前会话的那条，别的留在队列里等转回去（队列本身有 10 分钟 TTL）。
2. **历史按会话分开**：`state.history` 以前是一条全局的，轮询之后会把私聊的内容
   当成"刚聊过的"塞进群聊那一轮的提示词里。现在每条历史带 `conv`，
   取窗口时按会话过滤（记忆整理那边也一样）。


### 固定回复池可以直接在界面里改

不接大模型时用的那些回复，**不用碰代码也不用改文件**，在控制台「固定回复」那一块直接编辑：

- **一行一句**，会随机挑并避开最近发过的 6 句
- 句子里可以用 `{sender}` 代指对方昵称、`{echo}` 复述对方的话
- 每项都有徽章标明**「默认」还是「已自定义」**，可以逐项或整体恢复默认
- 接管模式那 6 项单独归一组（可爱语气），不会和普通模式混在一起

**配置怎么存的**：内置默认留在代码里（唯一事实来源），
`config.json` **只存你改动过的那几项**。

```json
"fallback": {
  "pools": {
    "greeting": ["你好呀", "嗨", "在的"]     // 只有改过的键才会出现
  }
}
```

这样配置文件不会被几百行默认值撑大，改默认值也不用同步两处。
把某项改回默认，那个键会被**删掉**而不是写一个等值的数组进去。

**优先级**（高 → 低）：

1. `config.fallback.pools.<键>` —— 控制台写的就是这里
2. `config.fallback.generic` —— **老配置项**，只对应兜底池
3. `BUILTIN_POOLS.<键>` —— 内置默认

> 第 2 条是兼容性要求。重构时我漏掉了它，导致早期版本配的 `fallback.generic`
> **静默失效** —— 被 `test-rules.mjs` 抓到了（它断言"改 fallback.generic 后
> 回复要变"，结果没变）。空数组一律视为"没改"，回退到下一优先级，
> 避免误把某个池清空成一句话都发不出。

### 它是怎么做的（零依赖）

这台机器**没有 npm**，装不了 Electron / Tauri 之类。所以控制台是：

- **Node 内置 `http` 模块**起一个小服务，**只绑 `127.0.0.1`**（外部访问不到，且二次校验来源 IP）
- 界面是**内嵌的 HTML**（`gui/page.js`），原生 JS，**不引用任何 CDN**
- 日志用 **SSE** 实时推送，SSE 断了还有 5 秒轮询兜底
- 控制台是机器人进程的**父进程**：关掉控制台（或 Ctrl+C）机器人会一起停，不留孤儿进程

两个安全设计：

1. **写 `config.json` 只改指定字段**，其余键（含 `$comment` 注释）原样保留 ——
   JSON 全量重写会把给人看的注释全丢掉。
2. **永远不信任界面传来的环境变量名**，用 `^[A-Za-z_][A-Za-z0-9_]*$` 校验后才写 `.env`。

### ⚠️ 双击打不开的三个原因（都实测过）

**原因 1：`.cmd` 里有中文。**

这个文件原本是 **UTF-8 无 BOM**，而 **cmd 按系统 ANSI 代码页（中文系统是 GBK）
读批处理文件**。于是所有中文变成乱码，更糟的是**乱码在行首会被当成命令去执行**：

```
实测输出：
  '.0.0.1:' is not recognized as an internal or external command
  '起来需要一两秒，浏览器会自己重试）' is not recognized
```

脚本执行到第一处就崩了，`start` 那行根本没跑到。

**修法**：`.cmd` 里**一律只用 ASCII**（注释、echo 全用英文）。
中文文件名没问题（文件系统层面是 UTF-16），**只有文件内容**受代码页影响。

> 这个坑**踩了两次** —— 第二次是我为了给你看中文提示，又往 `.cmd` 里加了中文。
> 所以现在 `test-gui.mjs` 里有一条断言专门守它：**`.cmd` 出现任何非 ASCII 字节就报错**。

**原因 2：换行是裸 LF，不是 CRLF。**

同一个守卫顺手抓到的：两个 `.cmd` 都是裸 LF（36 处、62 处）。
老式 cmd 对 LF 的容忍度不一致，**多行的 `if (...)` 块尤其容易出问题**
（实测那段"已在运行"的提示根本没打印出来，原因就是它）。

**修法**：`.cmd` 一律 CRLF。守卫里也有断言。

**原因 3：重复双击导致 EADDRINUSE 崩溃。**

控制台**已经在跑**的时候再双击一次，node 想再起一个实例 → 端口冲突 →
`Error: listen EADDRINUSE: address already in use 127.0.0.1:7788` → 崩掉。
浏览器那一刻打开，正好撞上崩溃或之后的空窗，看起来就是"打不开"。

**修法**：启动器**先探测端口**，已经在跑就只打开浏览器、不再起进程：

```
A console is already running on port 7788.
Opening it in your browser. Nothing new was started.
```

这样双击是**幂等**的 —— 点几次都能到达一个能用的界面。

> **探测用 `errorlevel`，不要用 `for /f` 捕获输出。**
> 实测：带嵌套引号的 powershell 命令塞进 `for /f` 之后会被引号解析搞坏，
> **永远返回"没在运行"**，检查静默失效 —— 于是照样崩。
> 改成 `powershell -Command "...; exit 0/1"` 然后判 `errorlevel` 才可靠。

### ⚠️ 检测进程时别把"命令行里含某字符串"当成匹配

排查过程中我几次被这个骗到：

- 查 `*bot.js*` 时匹配到了**查询命令自己**的命令行（里面含这串字符），
  于是一个不存在的进程反复"存活"，白查了好几轮
- 查 `gui/server.js` 时匹配到了**DSH 的作业壳**
  （`dsh-subprocess-local\lib\runner.js gui/server.js`），
  于是"控制台有 2 个进程"的假警报

**修法**：匹配进程时排除 `subprocess-local`，并且比对**完整命令行**而不是子串。

### 写界面时踩的两个坑（都有测试守着）

**1. 对象字面量里不能用表达式当键。**

```js
'llm.providers.' + provider + '.model': value   // ✗ 语法错误，整个脚本不执行
['llm.providers.' + provider + '.model']: value // ✓ 要加方括号
```

这个错误**让整个页面脚本静默失效** —— 界面看着正常出来，但所有输入框都是空的。
而当时的接口测试**全绿**，因为那些测试只测 HTTP，没跑页面里的 JS。

**2. 模板字符串会吃掉转义序列。** `gui/page.js` 本身是模板字符串，
里面写给浏览器执行的代码如果含 `\n`，会被**求值成真换行**输出到 HTML，
把字符串字面量当场截断。注释里出现它也一样会截断注释行。必须写成 `\\n`。

因为踩了这两次，`tools/test-gui.mjs` 现在会：
把页面里的 `<script>` 抽出来单独做语法检查，并核对**每个输入控件都在脚本里被赋值**
（防止"控件加了但忘了填"）。

## 配 API Key（机器人独立运行的关键）

**推荐：放进项目自己的 `.env`**

```powershell

copy .env.example .env
```

### 为什么不用 DSH 的凭据目录读 key

key 最初是从 `%APPDATA%\dsh-desktop\harness\.credentials.yaml` 读的。
那样有个隐患：**DSH 一卸载、或配置被清掉，机器人就退回本地规则，回复质量掉一大截**。

现在 key 放在项目自己目录下，**机器人完全独立** —— 关掉 DSH、甚至卸载它都能正常调模型。

实测（清掉 `DSH_HOME` / `DSH_WEB_URL` / `DSH_SESSION_ID` / `DEEPSEEK_API_KEY` 全部环境变量后）：

```

调用结果: ✓ "躺着呢 有点困" (254ms, deepseek-flash)
```

key 的来源会标注清楚，便于排错：

| `apiKeySource` | 含义 |
|---|---|
| `.env:DEEPSEEK_API_KEY` | 来自项目 `.env`（推荐） |
| `env:DEEPSEEK_API_KEY` | 来自系统环境变量 |
| `config.json(deepseek)` | 写在 `config.json` 里 |
| `none` | 没配 → 会走本地规则 |

**没配 key 不会报错**，会静默降级到本地规则。所以启动 banner 和 `node src/doctor.js`
都会明确写 `key=none` 并告诉你怎么配 —— 看到日志里 `来源=fallback` 就是没走到模型。

### 关于「免费」

**API 是计费的，不是免费的。** Kimi 的网页版聊天免费，但那是网页产品；

### 为什么不做「自动操作网页版聊天」

有人会想：既然网页版免费，能不能让脚本自动打开 `chat.deepseek.com`、
把提示词贴进去、再把回复抓回来？

**不做，两个原因：**

1. **违反服务条款。** 用脚本自动登录、自动发消息、抓取回复，是那家产品明令禁止的
   自动化访问。官方提供 API 就是为了这个用途。
2. **必然在你机器上制造破坏。** 要自动化就必须复用你的登录态 ——
   用独立浏览器配置你每次都得重新登录（就不叫全自动了），复用你正在用的 Chrome
   配置，脚本的会话状态就可能冲掉你的登录。而且网页端是 WebSocket 流式渲染，
   没有稳定的取值接口，只能靠"找一个长得像回复的 DOM 元素"，改版即失效。

**关键是：这条路本来就不必要。** 机器人调 API 是**独立进程**，
不需要 DSH、不需要浏览器、不需要登录态——只要 `.env` 里有 key 就行。

想省钱的话，正当办法是：调小 `llm.contextMessages`、调低 `replyProbability`、
或换个更便宜的模型（`glm-4.5-air` 那档通常最便宜）。

用 `node tools/test-provider.mjs` 可以验证多厂商解析（12 个用例）。

## 两条需求是怎么落地的

### 需求 1：启动时监测消息并恰当回复

```
capture-window.ps1  →  ocr-image.ps1  →  parse.js  →  gate.js  →  llm.js  →  sender.js
   截图(PrintWindow)      OCR 成文本行      还原消息      决定回不回    生成回复    发出去
```

- `parse.js` 用**左右对齐**区分消息归属：他人消息左对齐、自己消息右对齐。
  这同时解决了「排除自己的消息」和「排除左侧会话列表」两件事。
- `gate.js` 五道闸门：白名单 → 只回他人 → 去重 → 冷却/频率 → 群里必须被 @。

#### 冷却和待回复队列（一个踩过的坑）

冷却闸门最初只作用在「本轮扫描」内，被挡下的消息**直接丢弃**。
但下一轮扫描会重新发现同一条消息、重新撞冷却、再丢弃 ——
**冷却永远重置，这些消息永远发不出去**。单轮扫描完全看不出来，只有连续扫描才会暴露。

修法：被冷却挡下的消息进入 `state.json` 的 `pending` 队列，
每轮扫描**最多发一条**，冷却是**跨轮**计时的。于是：

```
第 1 轮：6 条全部入队，发第 1 条          → 队列剩 5
第 2 轮：(立刻) 冷却未过，一条都不发       → 队列剩 5   ← 关键：不重新入队、不丢弃
第 3 轮：(9 秒后) 冷却已过，从队列取 1 条  → 队列剩 4
```

队列项有 10 分钟 TTL（消息可能已经滚出屏幕），发送失败会留在队列里下轮重试。

### 需求 2：API 没被调用时，被 @ 也能简单回复

**API 是否可用，和「要不要回复」完全解耦。**

- `llm.js` 把「超时 / HTTP 错误 / 网络错误 / 没配 key / 被关闭」全部转成 `ok:false`，**不抛异常**。
- `bot.js` 拿到 `ok:false` 后自动调用 `fallback.js` 的本地规则回复。
- 群里被 @ 的判定在 `gate.js`，不碰网络，所以网络断了照样能触发。

降级链路：

```
大模型可用  → 生成回复，来源标 llm
大模型失败  → 匹配本地规则（"在吗"→"在的"……），来源标 fallback:rule
规则没命中  → 随机通用话术，来源标 fallback:generic
都拿不到    → defaultReply 兜底
```

日志里会写明每次回复的来源，例如：

```
→ "在的"   来源=fallback:rule  API 不可用(no-key: 缺少 API key) → 本地规则降级 命中规则 /在吗|在不在|在么/
```

## 发送节奏与回复自然度

### 发送间隔已关闭

`config.json` 的 `trigger.cooldownMs` 和 `maxRepliesPerMinute` 都设为 **0 = 不限速**。
主循环改成**一轮扫描把队列排空**（按时间先进先出，保持对话顺序）。

> **代价**：如果队列里积压了历史消息，一开启就会连着全发出去。
> 想只回新消息，先删 `state.json`。
> 另外 QQ 对短时间高频消息有风控，真遇到限流就把 `maxRepliesPerMinute` 设个非零值。

### 有选择地回复：被 @ 必回，其他按概率

`config.json` 的 `trigger.replyProbability`（0~1）：

| 设置 | 行为 |
|---|---|
| `0.25` | 未被 @ 的群消息大约 1/4 会回，其余只记下来 |
| `1` | 全回（等价于旧行为） |
| `0` | 只在被 @ 时回（比 `replyInGroupOnlyWhenMentioned` 更严格，因为后者只管群聊） |

`mentionAlwaysReplies`（默认 `true`）控制被 @ 时是否必回。设成 `false` 则被 @ 也按概率抽。

> **实现上的关键点**：骰子只在**决策入队时掷一次**，结果（`roll` 值）随消息冻结进
> `state.json` 的 pending 队列。
>
> 如果放到发送阶段每次重掷，同一条消息会被反复抽签 —— 概率失真，
> 低概率时甚至可能永远抽不中，表现成"消息被吞了"。

运行时统计行会显示闸门挡掉了多少条：

```
会话「示例群」群聊 | 白名单命中 | 消息 5 条 | 本轮新入队 1 条 | 队列剩余 1 条 | 概率挡下 4 条
```

用 `tools/test-gate.mjs` 验证（一万次抽样的统计断言）：

```
被 @ 的消必须必回（哪怕概率设得很低）   2000/2000
未被 @ 的消息回复率应接近配置值        回复率 24.83% 接近 25%
概率 0 → 一条都不回
概率 1 → 全部回
```

### 回复怎么读起来像人

见 `src/fallback.js`。核心是**避开"客服腔"**：

| 不用（一眼假） | 改用 |
|---|---|
| 收到，我看看 | 嗯嗯 / 收到 / 诶我看看 |
| 在忙，稍后回你 | 在忙，等下 |
| 感谢您的耐心等待 | 客气 / 没事 |
| 完整句子 + 感叹号 | 短到两三个字，或只有 `？`、`草`、`hh` |
| 纯文字 | 少量颜文字 `(・∀・)`、`(´･_･\`)`、`(≧▽≦)` |

四个技术手段：

1. **意图分类**（打招呼 / 问句 / 感谢 / 道歉 / 晚安 / 笑 / 附和 / 吐槽 / 约时间 / 被认出是机器人）
2. **每个意图一组回复**，随机挑
3. **排除最近发过的 6 句**，不连着重复
4. **种子里混入「已发送条数」**，同一句话被反复问会轮转，而不是永远同一句

**意图顺序是个坑**：具体意图必须排在笼统意图之前。
一开始 `question` 放在前面，把「明天几点」（该走 `meeting`）和「你是不是机器人」
（该走 `ask_if_bot`）全抢走了。问句判定现在排最后。

**另一个坑**：种子只用消息文本的话，同一句「在吗」问 5 次会给 5 次一模一样的回复。
混入「已发送条数」后才变成 `嗨 / 在的 / 欸，在 / 你好呀 / 在的`。

实测效果（群里真实跑出来的）：

```
回复 "在"                → "好，我记着了"
回复 [群友辛的怎么改] "？"   → "应该可以吧"
回复 [完了完了] "6点"        → "嗯嗯，等下回你"
回复 [群友辛的怎么改] "25点" → "群友辛的怎么改，我待会儿回你"   ← template，带昵称
回复 "还好deepseek比较便宜" → "嗯，自动的"                  ← ask_if_bot
```

### ⚠️ 但本地规则的极限在哪

**本地规则再扩也是有限短语池。** 它：

- 理解不了上下文（前面聊了什么它不知道）
- 组合数有限，聊久了还是能看出重复
- 回答不针对具体内容（问「怎么改配置」和问「今天几号」可能拿到同一类回复）

**想要真正自然的回复，配 `DEEPSEEK_API_KEY`。** 有 key 就走大模型，
每句都不一样、能接上下文；没 key 才落到这些本地规则。

## 对话上下文：一层一层挖下去的过程

这一节记的是**怎么一步步做到"能接上话"**的，包含三次踩坑。前面那节讲结论，
这里讲过程和为什么。

**第一版：只发屏幕上可见的几条** —— 滚出画面就没了，
于是模型经常接不上话、反复问已经说过的事。

**发现：Chromium 的无障碍树会把滚出视口上方的内容也暴露出来**，坐标是**负的**。
实测一次能拿到十几条真实历史消息：

```
y=-992  ← 搞完        我的token
y=-892  → 我          3.1415926…后面忘了
y=-692  → 我          笑死 你还有token呢
y=-592  ← 完了完了       @示例昵称一直学群主说话
y=-492  → 我          哈哈哈哈哈我学得像不像
y=-392  ← 搞完        她识别不到谁是群主吧
y= 273  ← 搞完        没有上下文理解
y= 953  ← 搞完        我去改一下吧
```

所以 `chatYMinOffset = -2400`（**故意的负值**）把这些历史收进来当上下文。
之前用 `-660` 全丢了，很浪费 —— 现成的长上下文就摆在那儿。

**上下文的真实作用**（实测对比）：

```
前文: 群友丙「周三下午两点开会，你来不来」→ 我「周三我有课 去不了」→ 群友丙「那周四呢」
要回: 群友丙「算了你周四也有课吧」

【无上下文】→ 嗯 有课 上午满的(´･_･`)     ← 顺着对方说，还编了「上午满的」
【有上下文】→ 周四真没课 你咋不信我        ← 看了历史，知道要纠正对方
```

**没上下文时模型会顺着对方的话编内容。** 这是最实际的差别。

`llm.contextMessages`（默认 16）控制发多少条给模型。

### ⚠️ 上下文这块踩过的三个坑

**1. 自己的消息被 x 范围过滤掉了**，导致上下文里只有别人说的话。
我的 x 范围是按「他人消息」设计的（内容起笔 x≈1709，中心 ≤1966），
而**右对齐的长句会伸到 2122**，用中心点判就越界丢掉了。

```
x=1929 w=193 → 右沿 2122 > xMax 1966 → 被丢掉
```

修法：自己消息单独一套 x 范围（`selfXMinOffset` / `selfXMaxOffset`）。

**2. 会话名读成空字符串。** `titleBarRatio.bottom = 0.17` 是按**逻辑窗口高 640** 算的
（上限 108），但 **UIA 坐标是物理空间（1200x800）**，标题实际在 y≈558 —— 永远超出范围。
UIA 路线的几何参数**必须全部用「相对发送按钮的偏移」**，不能混按窗口尺寸算的比例。

**3. 会话名取错成了「更多」。** 侧栏的「更多」按钮（x=1574）比会话名（x=1641）还靠左，
「取最靠左的」这个判据会选错。改成**取最宽的**（会话名 157 宽 vs 按钮 33~40 宽）。

### 自己发的消息也能认出来

右对齐就是自己发的（阈值 `selfXMinOffset`）。这让两件事变好了：

- **上下文完整了**：对话流里能标出哪句是自己说的
- **不会自己回自己**：`side='self'` 的消息在闸门层直接跳过

```
→ 回复  "我的token"              (通过全部闸门)
  跳过  "3.1415926…后面忘了"      (自己发的消息)
  跳过  "笑死 那你背"             (自己发的消息)
  跳过  "哈哈哈哈哈我学得像不像"    (自己发的消息)
```

防自嗨是**双保险**：这条的 side 判定 + `gate.js` 的 `sentReplies` 文本比对。

## AI 接管模式

**一句话定义**：接管期间由大模型按人设提示词代答，关闭后由本地固定回复池代答。
两者的分界是"这轮要不要花一次 API 请求"，不是"要不要回"。

在群里（或私聊）说一句 **`你接管`** 即可开启：

- 回复**全部由大模型生成**（不再走本地规则池）
- 语气按**当前人设**的提示词（`personas/<名字>.json`；没建过人设时用 `config.json` 的 `persona.systemPrompt`）
- 想让它下岗：说 **`你下班`** / `停止接管` / `自己回`

| 触发词（开启） | 触发词（关闭） |
|---|---|
| `你接管`、`你来接管`、`接管吧`、`你上` | `你下班`、`停止接管`、`自己回`、`别接管了` |

**开关存在 `state.json` 的 `takeoverEnabled`**，所以运行时切换**不用重启**；
`config.json` 里的 `persona.enabled` 只是「默认值」（state 里没有记录时用它）。
切换时它会回一句应答（默认「来了来了」/「那我撤了」）。指令消息本身不会被当成普通消息回复。

控制台「接入 API」页里那张卡把这六件事列成了对照表：作用 / 生效范围 / 切换方式 /
状态存放 / 大模型调用 / 调用失败怎么办。

### 接管期间：每条都回

接管的意义是替你聊，只回四分之一会让对话断断续续。所以接管期间
**生效概率自动升到 100%**，说「你下班」后恢复配置值（25%）。

启动 banner 会写明这一点，不会让你误以为还是 25%：

```
回复概率    : 被@ 必回 ／ 其他消息 100%  ← 接管模式自动提升（配置值 25%）
接管模式    : 已开启（每条都回，回复由大模型生成，可爱语气）
```

想保留概率就把 `persona.replyAllWhenActive` 设为 `false`。

> **实现位置**：`takeover.effectiveReplyProbability(state, cfg)`。
> 它不 import `gate.js`——`gate.js` 已经 import 了 config/parse，反向 import 会成环，
> 所以状态由调用方传进去。

### 人设提示词（现在是一个可切换的「身份」）

一份人设 = **提示词 + 它过的人生 + 它自己的记忆**，三者一起切换：

| 文件 | 是什么 |
|---|---|
| `personas/<名字>.json` | 说话方式、设定（接管模式发给大模型的就是它） |
| `lives/<名字>.json` | 它过的那段日子（人生模拟） |
| `memory/<名字>/` | 它自己的记忆（跟别人设完全分开） |

提示词写成一个字符串数组（按行读起来清楚）：

```
【最重要】读起来要像一个真人在手机上随手打的，不能像客服或AI：
· 短。常见 2~12 个字
· 口语化，可以有「诶」「欸」「嗯」「啊这」「草」「笑死」「hh」
· 偶尔只回一个颜文字，比如 (・∀・) (´･_･`) (≧▽≦) ？？
· 绝对不要「好的」「收到」「感谢」「请问」这类客服用语

【可爱】要可爱得自然：
· 偶尔卖萌、装傻，但不要每句都可爱，那样会腻
· 反差感重要：大部分时候正常聊天，偶尔冒一句可爱的

【分寸】
· 不懂就说不懂（「不知道诶」「？？」），不要硬编
· 对方情绪低落时先接住情绪，不要开玩笑
```

实测效果（真实 API 返回）：

```
在干嘛呢            → 刚瘫床上刷手机呢 咋啦
我这破电脑又蓝屏了   → 啊这 又蓝了？
明天几点开会？       → 不知道诶 问下群友辛呗
好烦啊不想上班       → 咋啦 又被老板搞了？      ← 情绪低落时不卖萌，先接情绪
```

**为什么提示词在人设文件里、而不是继续放 `config.json`**（这一段是踩出来的）：
`config.json` 是机器人**启动时读一次就缓存住**的，提示词放那儿就等于
「换一次人设要重启一次机器人」。而换人设跟换人生是同一类操作，
用户期望的是**点了立刻生效**。所以每份人设单独一个文件，用到的时候现读 ——
控制台里点「切过来」「保存提示词」都是立刻生效（只写 `state.json`，不重启）。

**没建过任何人设时行为完全不变**：用 `config.json` 的 `persona.systemPrompt`，
记忆也还是老路径（`memory.json` + `memory/*.json`）。第一次打开控制台会自动把
那份提示词搬成一份叫「默认」的人设，所以升级上来不会看到"人设没了"。

> ⚠ **提示词为空的人设切不过去**（控制台直接拦住）。空提示词会让 API 报错、
> 然后静默降级成本地固定回复 —— 表现成"接管明明开着，回复却很机械"，这种最难查。
>
> ⚠ **删人设不删记忆和人生**：删的是"怎么说话"，不是"发生过什么"。
> 后者删了不可逆，而且用户多半只是不想要这个身份了。

### 语气一致性：API 断了也不会掉回客服腔

接管模式的回复是**两级**：先让模型生成；只有那一次**调不通**时，才退回本地池子，
而且用的是**可爱版本**（`persona.fallbackGreeting` 等）——
所以即使 API 超时，语气也不会突然从「诶嘿」变成「收到，我看看」。

日志里的 `来源` 能区分：

| 来源 | 含义 |
|---|---|
| `llm:persona` | 接管模式，大模型生成 ✓ |
| `llm` | 普通模式，大模型生成 |
| `fallback:intent:persona` | 接管模式但 API 不可用，用了可爱语气池 |
| `silent` + `按配置不发兜底话` | 接管模式、API 不可用，而且关掉了下面的开关 → 这条不回 |

**模型调不通时到底发不发那句兜底话，现在可以选**（控制台「接入 API → AI 接管模式」里勾）：

```json
"reply": { "fallbackWhenApiDown": false }
```

- `true`（默认）= 用本地池子顶一句，别在被 @ 的时候装死
- `false` = 这条**不回**（宁可不回，也不发容易穿帮的罐头话）；日志会写一行说明，
  5 分钟内不重复报同一条，免得刷屏

> ⚠ 这个键在 2026-10-06 之前是**死配置**：`config.json` 里写着、全项目没有任何代码读它，
> 改成 `false` 行为一点不变、也不报错。现在 `src/takeover.js` 的
> `fallbackAllowedAfterApiFailure()` 真的用它了，测试里也钉着"bot.js 别把它接成死线"。
>
> 它只管「请求**发出去了**却失败/超时/返回空」这一种情况。下面三种不算故障，
> 仍然用本地回复：非接管模式（本来就不调 API）、`llm.enabled=false`（主动关掉大模型）、
> 没配 key（控制台一直明说会退化成固定话术，那是预告过的降级）。

### ⚠️ 一个踩过的坑：systemPrompt 写成数组要规范化

`persona.systemPrompt` 写成数组是为了配置可读，但**API 的 `content` 必须是字符串**。
直接传数组会让 API 报错 → 悄悄降级到本地规则，表现成「接管开着但回复不像模型生成的」。
`src/takeover.js` 的 `normalizePrompt()` 负责拼成字符串，有回归测试守着。

## 怎么人工改回复

改完**必须重启机器人**才会生效（`Ctrl+C` 停掉再 `node src/bot.js --watch`）。

匹配顺序：**内置意图 → 配置 rules → 模板 → 配置 generic → 内置 GENERIC → defaultReply**

### 方式 1：改兜底池（最省事，影响最大）

`config.json` 的 `fallback.generic`。**任何意图都没命中的消息**都从这里挑：

```json
"generic": ["嗯嗯", "收到", "在忙，等下", "回头说"]
```

### 方式 2：加自己的关键词（最常用）

**控制台里点着加**：控制台 →「未接入 API」页 →「自定义规则」→ `+ 添加一条规则`。
加完用下面的「试打一句」当场验（用的是还没保存的那份，不用先保存）。

手改 `config.json` 也可以，格式一样 —— `match` 是正则，`replies` 是候选池：

```json
"rules": [
  { "match": "年会|复盘|周报", "replies": ["周报我周五写", "年会的事我看下", "晚点给你"] }
]
```

`replies` **一定要写多句**，只写一句就会一直回那句，很快露馅。

> 界面里加规则时，写成不是合法正则（比如少个括号）**不会**让这条规则变死代码：
> 会退化成「包含这段字」来匹配，并在那条规则下面写清楚。
> 规则条目在保存时会清洗一遍：缺匹配写法或没写回复的条目直接丢掉 ——
> 空的 `match` 最危险，`new RegExp('')` 匹配一切，会把**所有**消息都吃掉。

### 方式 3：改内置意图的回复

编辑 `src/fallback.js` 顶部的 `INTENTS`，每个意图都有自己的 `replies` 数组：

```js
{
  id: 'greeting',
  test: (t) => /^(你好|嗨|在吗|在不在|早)/i.test(t),
  replies: ['在', '嗯在', '在的', '(・∀・)'],   // ← 改这里
},
```

现有的意图 id：`ask_if_bot` / `meeting` / `greeting` / `thanks` / `apology` /
`goodnight` / `laughter` / `complaint` / `agreement` / `question`

### ⚠️ 一个必须知道的陷阱：内置意图很"贪"

默认顺序是**内置意图在前**。所以你在配置里给「在吗」写规则**不会生效**——
`greeting` 意图会先把它抢走。「周报写了吗」也一样，结尾的「吗」会命中 `question`。

**想让配置规则优先，打开这个开关：**

```json
"customRulesFirst": true
```

打开后匹配顺序变成 **配置 rules → 内置意图 → ……**，你的规则就能覆盖内置意图了。

用 `node tools/test-rules.mjs` 可以验证这两种优先级（15 个用例）。

### 各来源的日志标记

回复日志会写来源，便于确认你改的那条到底有没有被用到：

| 日志里的 `来源=` | 含义 |
|---|---|
| `intent:greeting` | 命中了内置意图（但你的规则没生效，可能被抢了） |
| `rule` | 命中了 `config.json` 的 `rules` ✓ |
| `template` | 用了带昵称/复述的模板接话 |
| `generic` | 用了兜底池 |
| `default` | 落到 `defaultReply` |

### 想彻底换掉这套规则？

配 `$env:DEEPSEEK_API_KEY`，回复就由大模型生成，本地的 `INTENTS` / `rules` / `generic`
都不再参与（只在 API 失败时兜底）。那才是"改回复"的终极方式——直接改 `llm.systemPrompt`：

```json
"systemPrompt": "你在替一个 QQ 用户回复群消息。语气随意、简短，像大学生群里说话，不要礼貌用语，不要自称AI。只输出回复正文。"
```

## 几何参数标定（换分辨率必读）

`config.json` 的 `geometry` 全部来自 **960×640 窗口的实测**：

| 参数 | 值 | 依据 |
|---|---|---|
| `messageAreaRatio.left` | 0.31 | 排除左侧侧栏 + 会话列表（约 300px） |
| `messageAreaRatio.top` | 0.14 | 标题栏下方 |
| `messageAreaRatio.bottom` | 0.82 | 输入框上方（输入框提示在 y≈0.93 处） |
| `titleBarRatio.bottom` | 0.17 | 覆盖到 y≈110 |
| `titleLeftRatio` | 0.22 | **关键**：标题栏横跨整窗，左半是自己昵称，会话名在右侧面板上方 |
| `selfLeftRatio` | 0.82 | 自己消息右对齐（实测起笔 x≈0.89），他人起笔 0.48~0.51 |

**换分辨率或缩放后**：先 `node src/doctor.js`，看「解析」那项。
如果消息读不出来，改这几个比例，或者用 `geometry.messageAreaLeftPx` 之类的字段直接写像素值。
调规则时用 `node tools/parse-offline.mjs <ocr-json>` 反复试，比每次截图快得多。

## 已知限制（都是实测确认的，不是猜测）

1. **只能读屏幕上可见的那一屏。** 消息滚出去就看不到。OCR 不会补历史。
2. **图片、表情、语音、文件消息读不到**——没有文字可识别。这类消息会被整条跳过。
3. **会话名靠 OCR 识别**，可能出错（例：`示例群（10）` 识别正确，但字体/缩放变了可能糊）。
   白名单匹配用的是「归一化后包含」，比精确匹配宽容一些。
4. **发送者昵称几乎读不准**。实测渲染成 `LV100搞完` 这种带徽章的形式，OCR 只能给出 `LVI思完0@...` 这类碎片。
   所以**不要把逻辑建立在发送者名字上**，程序内部也不依赖它（只写进日志）。
5. **LV 徽章、头像、温度/状态条会产生 OCR 噪声。** 已用 `noiseTextPatterns` 过滤一部分，
   但无法根除。影响是「可能多回一次」，不会「漏掉消息」。
6. **窗口被其他窗口完全遮住时**依赖 `PrintWindow` 的 `PW_RENDERFULLCONTENT`；
   目前实测遮挡情况下也能截到，但 Electron 版本差异可能改变这个行为。
7. **发送靠剪贴板 + Ctrl+V + 回车**。会临时占用剪贴板，脚本会在发送后还原原内容。
   发送前会把窗口提到前台；**提不到前台就放弃发送**，避免把字打进别的窗口。

## 安全设计清单

这些不是装饰，是防止它变成一个乱发消息的脚本：

- 白名单**默认为空** → 默认状态下谁都不回
- `dryRun` **默认为 true** → 默认状态下什么都不发
- 目标窗口不可见 / 提不到前台 → **拒绝发送**
- 机器人自己发出去的文本会登记，扫描时读到就跳过 → **防「我回复→截到自己→再回复」死循环**
- `replyProbability` → 未被 @ 的消息按概率回，不会每条都插嘴
- 冷却 `cooldownMs` + 每分钟上限 `maxRepliesPerMinute` → 防刷屏（当前都设为 0 = 关闭）
- 同一条消息指纹只回一次 → 防重复
- **单实例锁** `.bot.lock` → 防两个实例同时跑导致同一条消息回两次
- 连续失败 5 次自动退避 → 窗口被关掉时不会疯狂刷日志
- 输入框非空且清不掉时 → **拒绝发送**，不发"垃圾+新回复"拼起来的乱码

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| `已有实例在运行（PID x）` | 单实例锁生效。先停掉那个进程，或删 `.bot.lock` |
| `截图失败: no usable window` | QQ 窗口最小化或在托盘里，打开它 |
| `解析: 消息 0 条` | 没进入某个聊天，或参数不匹配 → 跑 `node src/doctor.js` 看细节 |
| 群聊被判成私聊 | `detectGroupChat` 的证据都没命中 → 把群名填进 `trigger.groupNames` |
| 群头衔混进消息正文 | `geometry.uia.titleXThreshold` 需要按窗口调整（实测 1750） |
| 回复没发出去 | 看日志：`发送失败（stage=…）` 会带具体原因（窗口不可见 / 抓不到焦点 / 打字没读回） |
| 运行时不显示"概率挡下 N 条" | 说明当轮都被前面的闸门挡了（去重/白名单），或概率恰好全部命中 |
| 测试数在 12/13 之间跳 | 是老版本的问题；现在测试已改为确定性，应稳定在 16 |
| `无法识别的 *.ps1 路径` | 说明有 .ps1 被存成了无 BOM 的 UTF-8 且含中文。见下 |

### 一个必须记住的坑

**所有 `.ps1` 必须是 ASCII-only，或带 UTF-8 BOM。**

Windows PowerShell 5.1 会把**无 BOM 的 UTF-8** 当 ANSI(GBK) 解码。
中文注释会变成乱码 → 引号错位 → 语法错误；中文路径会变成 `Z:\������` → 找不到文件。
本项目的脚本用两种方式规避：工具脚本全 ASCII，Node 生成的临时脚本加 `\uFEFF`。
