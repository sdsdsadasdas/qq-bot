# QQ 自动回复机器人 — 使用说明

> **这是脱敏发布版。** 相对开发机上的完整工程，这里少了三样东西：
>
> | 少了什么 | 为什么 |
> |---|---|
> | `tools/fixtures/` | 实机 UIA 原始数据，含真实群名、群友昵称和**聊天内容原文** |
> | `tools/export-dist.mjs` | 脱敏工具本身，它的替换表里逐个写着要抹掉的昵称 |
> | `tools/test-export.mjs` | 上面那个工具的测试 |
>
> 因此 `node tools/test-parse-sender.mjs` 会打印"缺少实机夹具"并跳过 ——
> 那是**设计如此**，不是坏了。完整的结构说明见 `docs/开发记录.md`。


一个在 Windows 上运行的个人 QQ 自动回复程序。它不注入、不改 QQ 客户端，
而是通过**读取窗口的无障碍树（UIA）**获取聊天内容，并按配置生成回复。

- **接入大模型时**：AI 接管模式，回复由模型按人设提示词生成
- **不接大模型时**：本地固定回复池，按关键词/意图挑一句（不产生任何费用）

两种模式共用同一套"读消息 → 判断该不该回 → 发送"的流程，
区别只在于**这轮回复由谁生成**。

---

## 一、运行环境

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11 | 依赖 UIA 与 PowerShell，仅 Windows 可用 |
| QQ | QQ NT（新版 QQ） | 经典版布局不同，未适配 |
| Node.js | **18 以上**（实测 v24.9） | 运行机器人本体 |
| PowerShell | 5.1（系统自带） | 界面读取与点击由 `.ps1` 脚本完成 |
| npm 依赖 | **无** | 整个项目零第三方依赖，不需要联网装包 |

> 机器人运行期间 QQ 必须**保持登录并停在一个聊天页面上**（可以最小化到后台，
> 但窗口不能关闭）。它读的是当前打开的会话。

## 二、目录结构

```
├─ 机器人控制台.cmd        ← 双击这个启动（推荐入口）
├─ start-bot.cmd           ← 只启动机器人（不起控制台，会被拒绝启动）
├─ config.json             ← 主配置（唯一需要手改的文件）
├─ .env                     ← API 密钥（运行时生成，不要提交/外发）
├─ .env.example             ← 密钥文件模板
├─ src/                     ← 机器人本体
├─ gui/                     ← 图形控制台（内嵌页面，无 CDN 依赖）
├─ tools/                   ← PowerShell 脚本 + 离线测试
├─ docs/                    ← 这份使用说明（详细的踩坑过程在 README.md）
└─ 运行后自动生成：
   state.json               ← 运行状态（已处理过的消息、待回复队列、历史、当前人设/人生）
   personas/                ← 人设（一份文件 = 一个「身份」：提示词 + 它的人生）
   memory.json / memory/    ← 记忆（没人设时：总记忆 + 每个会话一份）
   memory/<人设>/           ← 有当前人设时：它自己的记忆（跟别人设完全分开）
   life.json / lives/       ← 人生模拟的生活日志
   logs/                    ← 运行日志（JSON Lines）
```

## 三、快速开始

### 1. 填机器人自己的名字（**必须**）

打开 `config.json`，找到 `trigger.botNames`，改成**你这个 QQ 号的昵称**：

```json
"botNames": ["你的QQ昵称"]
```

群聊里判断"有没有被 @"就靠这份名单。**写错的后果是它在群里一条都不会回**，
而且不报错。启动时自检会提醒，看到一个叫 `checkMentionNames` 的警告就是这件事。

### 2. 决定回复范围

```json
"trigger": {
  "replyScope": "whitelist",          // whitelist = 只回白名单；all = 所有会话都回
  "whitelist": ["你的测试群"]          // replyScope=whitelist 时生效，填会话名
}
```

**白名单为空 = 谁都不回**（这是刻意的安全默认）。想先在安全环境试，
就把自己建的测试群填进去。

### 3. 配置大模型（想用 AI 回复的话）

在控制台「接入 API」页里选厂商、填 **API Key**、点「检测服务」。
Key 会被写进项目根目录的 `.env`，不会进 `config.json`，也不会提交到版本库。

也可以完全跳过这一步 —— 那样就是纯本地回复模式，不花钱。

### 4. 先干跑，再真发

`config.json` 里 `reply.dryRun` **默认是 `true`**：只报告、不发送。
先在控制台启动机器人，看日志里"会回什么"，确认没问题后再把 `dryRun` 关掉。

### 5. 启动

**双击 `机器人控制台.cmd`** → 浏览器打开 `http://127.0.0.1:7788/` → 点「启动机器人」。

> 机器人**必须在控制台运行时才能启动**（这是刻意设计的：控制台是它的父进程，
> 关掉控制台机器人会一起停，不留孤儿进程）。单独双击 `start-bot.cmd`
> 会被拒绝，退出码 3。

## 四、控制台三个页面

| 页 | 内容 |
|---|---|
| **主界面** | 启停机器人、实时日志；折叠着的「自动轮询（会动鼠标）」 |
| **未接入 API** | 固定回复池 + 自定义规则（关键词 → 一组回复），以及"试打一句"验证 |
| **接入 API** | 厂商 / 模型名 / API Key / 地址 / 上下文条数 / 超时 / tokens / 思考开关；AI 接管模式；**人设**（提示词 + 它的人生 + 它的记忆，都是这张卡里的子项）；系统消息过滤 |

「回复行为」（白名单、回复概率、发送间隔、被 @ 必回、dryRun、长度上限）
两个模式都要用，所以那张卡会跟着当前页走，在「未接入 API」和「接入 API」两页都能改。

**改完必须点保存**（保存写 `config.json`），并且**重启机器人才生效** ——
AI 接管开关、人生模拟开关、记忆清空、**切换人设**是例外，
它们存在 `state.json` 里，点了立刻生效。

## 五、两种回复模式

### 不接 API：本地固定回复

按**意图**匹配（打招呼 / 问句 / 感谢 / 道歉 / 晚安 / 笑 / 吐槽 / 附和 / 约时间 /
被认出是机器人），每个意图配一组回复，随机挑一句并避开最近发过的 6 句。

想加自己的关键词，在控制台「未接入 API → 自定义规则」里加：
一条规则 = 一个**匹配写法**（正则；不会写就写关键词，用 `|` 隔开）+ 一组回复。

> ⚠ 内置意图默认**优先**于自定义规则。给「在吗」写规则是永远不会命中的 ——
> 打招呼意图会先把它接走。想覆盖，勾上「我的规则优先于内置意图」。

### 接 API：AI 接管模式

**定义**：接管期间由大模型按人设提示词代答；关闭后由本地固定回复池代答。
分界是"这轮要不要花一次 API 请求"，不是"要不要回"。

- 开启：在会话里发 `你接管`，或在控制台「接入 API」页勾选（立即生效，不用重启）
- 关闭：发 `你下班` / `停止接管` / `自己回`
- 只在接管模式开启时才调用大模型（`llm.callApiInTakeoverOnly=true`）
- 大模型**调不通**时的行为由 `reply.fallbackWhenApiDown` 决定：
  `true` 用本地池子顶一句；`false` 这条不回（宁可不回，也不发容易穿帮的罐头话）

### 人设：可切换的「身份」（提示词 + 它的人生 + 它的记忆）

**人设不只是一段提示词，而是一个身份**，它包含三样东西：

| 文件 | 是什么 |
|---|---|
| `personas/<名字>.json` | 说话方式、设定（接管模式下发给大模型的就是它） |
| `lives/<名字>.json` | 它过的那段日子（人生模拟的生活日志） |
| `memory/<名字>/` | 它自己的记忆（总记忆 + 每个会话一份） |

**切人设 = 这三样一起换。** 所以"小深"和"另一个角色"不会共用记忆，
也不会一个身份过着另一个身份的日子 —— 记忆串了不会报错，
只会表现得像"角色扮演崩了"，很难查。

在控制台「接入 API → 人设」卡片里操作：

| 操作 | 效果 |
|---|---|
| 选一份 + 「切过来」 | **立刻生效**（只写 `state.json`，不用重启） |
| 「新建」 | 建一个空白身份；勾上「复制当前这份当起点」= 连提示词、人生、记忆一起复制 |
| 改提示词 + 「保存提示词」 | **立刻生效**（提示词存在人设文件里，每次用到时现读） |
| 「删除」 | 只删这份人设。它的记忆和人生**留着** —— 删的是"怎么说话"，不是"发生过什么" |

第一次打开控制台会自动把 `config.json` 里的 `persona.systemPrompt`
搬成一份叫「默认」的人设，所以升级上来不会看到"人设没了"。

> ⚠ **提示词为空的人设切不过去**（控制台会直接拦住）。
> 空的提示词会让 API 报错、然后静默降级成本地固定回复 ——
> 表现成"接管明明开着，回复却很机械"，这种问题很难查。

> 提示词为什么放在人设文件里、而不是继续放 `config.json`：
> `config.json` 是启动时读一次就缓存住的，放那儿等于"换一次人设要重启一次机器人"。
> 而换人设跟换人生是同一类操作，用户期望的是点了立刻见效。

**没建过任何人设时，行为跟以前完全一样**：用 `config.json` 里那份提示词，
记忆也还是老路径（`memory.json` + `memory/*.json`）。

### 记忆与人生（人设这张卡里的两个子项）

展开「记忆」能看到：模型**实际读到的那段文字**、总记忆、以及**每个会话一份**的会话记忆。
会话那一行里，每个会话旁边都有两个动作，别搞混：

| 动作 | 效果 |
|---|---|
| 「清空这个会话的记忆」 | 把内容抹掉，**这个会话还留在列表里**（留个空壳，看得见"我清过它"） |
| 会话旁边的小「删」 | **连文件一起删掉**，列表里不再有它 —— 想彻底不要这个会话时用它 |

> 两者都只影响这一个会话：总记忆、其他会话、它的人生都不动。
> 删除是**不可逆**的（文件删了就没了），所以会先弹一次确认。

「人生」子项里可以开关人生模拟、开关主动分享、切换它过着谁的日子，
也可以新建/切换/清空。清空生活日志只清**当前这份人生**（切到别的份去清就是清那一份）。

## 六、监测多个会话（自动轮询）

QQ **一次只渲染一个聊天**，没有后台接口。想监测其它会话，只能替你点击会话列表
（点进去 → 读 → 再点下一个）。这个功能在「主界面 → 自动轮询」里，
**默认关闭**，因为它会移动你的鼠标、把 QQ 抢到前台。

| 配置 | 说明 |
|---|---|
| `scope` | `all` = 会话列表里每一个都轮（推荐，回不回仍由白名单决定）／`whitelist` = 只轮白名单／`list` = 只轮 `conversations` |
| `settleMs` | 切完等多久再读（默认 1500ms；太短会读到上一个会话的消息，会回错人） |
| `minGapMs` | 两次切换的间隔下限（默认 3000ms） |
| `pauseWhenActive` + `activeIdleMs` | **你一动键鼠就暂停**，闲置够了才继续（默认 4000ms） |

最后一条不是客气：Windows 不允许后台程序在你活跃时抢前台，
硬点的话那一下只会变成"激活窗口"，而你的光标已经被挪走、正在打的字会掉进 QQ 里。

## 七、运行方式（命令行）

```powershell
node src/bot.js --once      # 扫描一次就退出（配合 dryRun 最适合验证配置）
node src/bot.js --watch     # 持续监测（默认 4 秒一轮，±0.8 秒抖动）
node src/doctor.js          # 自检：逐项确认环境、UIA 布局、解析结果
```

离线测试（不需要 QQ，也不需要网络）：

```powershell
node tools/test-parse-sender.mjs   # 消息解析（含真实 UIA 夹具）
node tools/test-gate.mjs           # 该不该回、概率闸门
node tools/test-fallback.mjs       # 本地回复、自定义规则
node tools/test-memory.mjs         # 记忆合并
node tools/test-life.mjs           # 人生模拟
```

> ⚠ **这批测试是按"已经配好的机器人"写的**：有一小部分会去读 `config.json`，
> 断言的是开发机上的具体设置（机器人昵称、白名单、回复概率、人生模拟开着…）。
> 所以在一个**还没配置**的副本上，它们会有一部分显示失败 ——
> 失败的通常是「用真实配置，@自己的消息全部认出」这类**前置条件不满足**的项，
> 不是代码坏了。配好 `botNames` / 白名单之后再跑就有意义了。
> 想知道"我这台机器现在到底行不行"，用 `node src/doctor.js` —— 它是按你的配置逐项体检的。

## 八、常见问题

**它会回 QQ 自己的提示语吗（临时会话、防骗通知、撤回…）** —— 默认**不会**。
控制台「回复行为」里有「不回 QQ 自己的系统提示」开关，默认开着，内置 10 类规则：

| 类 | 例子 |
|---|---|
| 临时会话提示 | `临时会话` |
| 防骗提示 | `该用户通过“临时会话谨防兼职刷单…”` |
| 群成员变动 | `你已被移出群聊`、`群友甲加入了群聊` |
| 群管理/群设置通知 | `群主修改群名为「…」` |
| 好友关系提示 | `以上是打招呼的内容`、`对方已不是你的好友` |
| 撤回提示 | `张三撤回了一条消息` |
| 通话记录 | `语音通话`、`视频通话` |
| 戳一戳/拍一拍 | `群友甲拍了拍我` |
| 卡片消息 | `[图片]`、`[文件]`（**只认带方括号的形态**） |
| 时间分隔线 | `10:38` |

想加自己的：在同一处填「额外要屏蔽的关键词或正则」（逗号分隔，普通词按包含匹配、正则也行）。
配置项是 `trigger.ignoreSystemMessages` 和 `trigger.systemPatterns`。

> 规则刻意**不误伤真人**：「图片」「文件」「红包」这种**裸词不筛**
> —— 真人真的会只发这两个字。群通知也要求"整句没有标点"
> （通知是机器拼的，人说话一般带逗号句号）。加规则时请照这个标准来。

**机器人不回消息** —— 按顺序排查：
1. 白名单里有没有当前会话名（`replyScope=whitelist` 时为空 = 谁都不回）
2. `botNames` 是不是你的 QQ 昵称（群里靠它判断被 @）
3. 群聊里是否被 @（`replyGroupOnlyWhenMentioned` 打开时，没被 @ 不回）
4. 是否在 `dryRun`（只报告不发送）
5. 看日志最后一行"会话「X」… 本轮新入队 N 条"

**回复内容像是固定模板** —— 说明这轮没调用大模型。日志里 `来源=` 会写清楚：
`llm:persona` 是模型生成的；`fallback:...` 是本地池子（括号里会写原因，如 `API 不可用(timeout)`）。

**名字和内容粘在一起** —— 解析层的问题，先跑 `node tools/test-parse-sender.mjs`；
再跑 `node src/doctor.js` 看「发送者行锚点」那一行（`lv` / `avatar` / `none`）。
某些群整屏没有等级徽章，只能靠头像认发送者行。

**双击控制台打不开** —— 见「开发记录」里「⚠️ 双击打不开的三个原因」
（开发目录里是根目录的 `README.md`，发布包里是 `docs/开发记录.md`）；
最常见的是 Node 不在 PATH，启动器会在几个标准位置里找，找不到会打印找过哪里。

**回复很慢** —— 本地小模型的瓶颈通常在显存/内存不足导致的磁盘换入换出；
控制台日志里 `耗时` 和 `来源` 会给出实测数字。云厂商模型通常 1~3 秒。

## 九、数据、隐私与边界

- **回复是以你自己的 QQ 号身份发出的**，别人看到的就是你说的话。
  请在知情的前提下使用，别拿它冒充真人做承诺。
- **会读取会话内容**：当前打开的会话，以及（开启轮询时）会话列表里的其它会话。
  历史与记忆按会话隔离存放，但都在这台机器上明文保存。不想被读的会话
  加进 `trigger.blacklist`。
- **密钥只存在 `.env`**（项目根目录），不要连同 `.env` 一起发给别人。
- **会动鼠标**：只有"自动轮询"开启时会（可以设置成你不在时才轮）。
- **不需要管理员权限**，不注入 QQ 进程，不修改 QQ 文件。
- ⚠ **`tools/fixtures/` 里是实机抓下来的 UIA 原始数据**，含真实的 QQ 昵称与群名。
  它只被离线测试使用；要把这个文件夹发给别人之前，先删掉 `tools/fixtures/`。
- 导出这个包时，运行时数据（`state.json` / `memory*` / `life*` / `logs/` / `.env`）
  一律**不会**被带出去 —— 但你自己手动复制文件夹时要注意这一点。
